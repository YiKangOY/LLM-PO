# Timing → Power Recovery → Area Trim → Final Timing Touch-up 

**Design Summary:** The design is timing-limited with little slack; an initial timing push is expected to expose power/area inflation, so the flow assumes power and area are elevated afterward and finishes with a timing cleanup.
**Target selection:** Start with timing to create slack, then recover power, then trim area, then re-check timing at the end. If timing progress stalls, shift effort to power/area and come back for a final timing pass.
**Option selection:** Early **explore** diverse tool option combinations for timing to quickly fix easy issues and surface “unfixable reasons.” Then **exploit** targeted options aligned to those reasons; avoid repeating options that previously had no effect.
**Guidelines (timing/power/area):** Treat **setup vs hold** as separate timing sub-problems with independent explore/exploit control. Ignore truly non-fixable violations. After timing improvements (which may raise power/area), run power recovery focusing on the increased power component (or total power), then area recovery; only spend slack where safe. After power/area steps, do an incremental timing touch-up to repair any regressions.

# Setup Timing → Hold Timing → Power Recovery → Setup Re-check 

**Design Summary:** The design is dominated by setup violations with secondary hold issues; after closing both, power is likely worse, so a power pass is needed before re-checking setup for regressions.
**Target selection:** Prioritize **setup** closure first, then **hold**, then power; finish with a setup re-check to ensure hold/power didn’t reintroduce setup issues. If a stage stops improving, move on and preserve iterations for later re-checks.
**Option selection:** For each stage, begin with **exploration** across option combinations to reveal fixability and unfixable reasons; then **exploit** options matched to the dominant reasons and prior history, avoiding repeats with no benefit. With limited budget, either try one untried option (explore) or double down on the best-known fix (exploit).
**Guidelines:** Keep setup/hold handling distinct. Ignore non-fixable issues. Perform power optimization only after timing slack exists; if power optimization worsens timing, rely on the final setup re-check to restore timing. Track area side-effects; if timing fixes inflate area heavily, schedule a later area-focused pass (even if not in this sequence).
