
**COMMAND FORMAT AND OPTIONS:**
Command format: opt_timing -violation_type [setup|hold] -cell_class [cell_class] -actions [action] -site_mode [site_mode] (-area_cap [cap]) (-slack_above [slack_threshold1]) (-slack_below [slack_threshold2])
Available violation types: setup or hold, you can only choose one of them.
Available actions for setup: gate_sizing, gate_sizing_side_load, buffer_insertion, you can select one action each time. The most common choice is gate_sizing, then buffer_insertion, then gate_sizing_side_load.
Available actions for hold: gate_sizing, buffer_insertion, you can select one action each time. The most common choice is gate_sizing, then buffer_insertion.
Available cell classes: combinational, sequential, clock_tree, you can only choose one of them. If you do not choose combinational, then you can only use gate_sizing action. The most common cell class is combinational, then sequential, use clock_tree only if you find related unfixable reasons.
Available site modes: open_slot, occupied_slot. The common selection is open_slot, you can explore occupied_slot if you find the timing optimization result is not promising.
Optional -area_cap: Specify area increment cap for gate_sizing, only use it when gate_sizing option selected, default value is 2, available values are [4|8|10|12|16|20]. In exploration stage, use the default value, if you find related unfixable reasons, increase these value.
Optional -slack_above slack_threshold1: Default is 0. The slack_threshold1 can be set to a positive value, then the command will try to improve the timing of paths with slacks larger than the slack_threshold1 (aka more positive slacks). This may increase area and power but can further improve timing. Only use it in exploitation stage when you see WNS can not be optimized futher but there is still TNS violation. Also do not use it when the iteration budget is nearly exhausted to ensure there is time to make power/area recovery. Give pure number, no units.
Optional: -slack_below slack_threshold2: Default is 0. The slack_threshold2 can be set to a negative value, the command will NOT try to improve the timing of paths with slacks smaller than the slack_threshold2 (aka more negative slacks). This may limit the timing optimization but lead to reduced power and area incresing. Do not use it when you need substantial timing optimization. Give pure number, no units.
